1. NGUYÊN TẮC TRIỂN KHAI
======================================================================

- Triển khai theo milestone nhỏ.
- Mỗi milestone có branch riêng.
- Antigravity phải lập plan trước khi code.
- Không xây UI hoàn chỉnh trước khi media/bridge POC hoạt động.
- Không release nếu thiếu test.
- Không thay đổi kiến trúc mà không có ADR.
- Mỗi milestone phải tạo artifact kiểm chứng.

2. WORKFLOW CHUẨN CHO ANTIGRAVITY
======================================================================

1. Read:
   - Product Overview.
   - SRS.
   - Architecture.
   - ADR liên quan.
2. Inspect current repository.
3. Generate implementation plan.
4. Xác định file được sửa.
5. Tạo hoặc cập nhật test trước/song song code.
6. Implement.
7. Run:
   - format
   - lint
   - type check
   - unit test
   - integration test liên quan
8. Verify artifact.
9. Produce change report.
10. Commit theo conventional commits.
11. Không merge/publish nếu chưa được yêu cầu.

Report format:

14. GITHUB TWO-REPO WORKFLOW
======================================================================

Private Repo branches:
- main
- develop
- feature/*
- fix/*
- release/*

Public Repo:
- releases only.
- latest.yml per release/channel.
- binaries.
- changelog.

Pipeline:
1. Tag private repo.
2. Run full tests.
3. Build.
4. Scan.
5. Sign.
6. Generate checksum.
7. Publish public release.
8. Generate/publish latest.yml cuối cùng.
9. Verify download from public.
10. Mark release active.

Secret rules:
- GitHub Actions secrets.
- Least privilege token.
- Public repo token chỉ có quyền release cần thiết.
- Không echo secret.
- Không upload private source artifact.

20. ANTIGRAVITY TASK PROMPT — UPDATE MODULE
======================================================================

You are implementing the DTA AutoLive updater by adapting the existing
DTA Studio legacy specification.

Authoritative requirements:
- Splash Screen is the startup gatekeeper.
- Main Dashboard must remain hidden until version verification succeeds.
- Public Release Repository exposes latest.yml and release binaries.
- Private Source Repository publishes through a v* Git tag workflow.
- DTA_RELEASE_TOKEN exists only in GitHub Actions secrets.
- Strict Mode blocks startup when update verification cannot complete.
- Updates are mandatory and cannot be skipped.
- Download progress must be visible in real time.
- A separate updater process installs, restarts and rolls back.
- Preserve SHA-512 compatibility with the legacy updater.
- Adapt implementation to Python/PySide6; do not introduce Electron.

Required output:
- implementation plan
- files changed
- tests
- generated latest.yml fixture
- GitHub Actions workflow
- installer/updater artifact
- evidence that Main Dashboard never appears before update clearance
